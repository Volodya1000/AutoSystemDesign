# Явные параметры обслуживания

BRD задаёт бизнес-функции и нагрузку, но обычно не содержит времени обработки
и числа независимых каналов. Лимит одновременных запросов не равен этому числу.
Поэтому без заданных каналов оценка ожидания остаётся неизвестной.

Внешний JSON-каталог позволяет задать параметры независимо от LLM:

```bash
uv run python scripts/generate_pipeline.py --scenario output/presentation_run_01/online_store_demo.yaml --profiles examples/performance/online_store_profiles.json --out-dir output/profiled_run --diagram-server http://localhost:8080 --diagram-format png
```

`by_node_type` задаёт явный профиль типа компонента, `by_node_id` имеет приоритет
для конкретного ID. Каждый профиль содержит источник `source` и происхождение
`provenance`: `assumption` либо `measurement`. Эти значения описывает автор
каталога; программа не подтверждает наличие внешних измерений.

Обязательны параметры реплик, concurrency, очереди, независимых каналов,
среднего времени обработки, стандартного отклонения и месячной стоимости.
Каналы не могут превышать concurrency; нечисловые/бесконечные значения и
неизвестные поля отклоняются. Профиль заменяет все перечисленные значения,
сохраняя топологию и свойства конкретного типа узла.

Параметры привязываются до проверки C4. Именно этот граф сохраняется и передаётся
во все последующие стадии. Применённые профили с источниками сохраняются в
`<identifier>_service_profiles.json`. Для узла без подходящего профиля при явно
включённом каталоге формируется ошибка исправления, а не молчаливый откат к числам LLM.
Без каталога сохраняется прежнее поведение, включая `null` для неизвестных задержек.

Каталог можно также задать в `config.yaml` в поле `service_profiles` как объект
или путь к JSON относительно рабочего каталога. Параметр CLI имеет приоритет.

## Проверка без LLM

```bash
uv run python scripts/analyze_profiled_architecture.py --graph examples/performance/online_store_graph.json --scenario examples/performance/online_store_scenario.yaml --profiles examples/performance/online_store_profiles.json --out-dir output/profiled_offline
```

Это фиксированный синтетический пример с двумя функциями и одним API заказов
за балансировщиком. Команда вызывает существующий расчёт и PDF-рендерер программы.
Она создаёт принятый граф, применённые профили, JSON и PDF анализа; Sequence/API
эта офлайн-команда не генерирует.

Числа примера — иллюстративные допущения, а не измерения реального магазина.
Средняя задержка не доказывает соблюдение p95. Конечные очереди и другие
ограничения аналитики сохраняются, поэтому `partial` допустим даже при
наличии рассчитанного критического пути. Полная независимая научная калибровка
и oracle остаются отдельными задачами #146/#159.
