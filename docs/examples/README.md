# Примеры для презентации

Этот каталог содержит автономный снимок демонстрационного входа. Файл `social_network_chat.yaml` скопирован из канонического сценария `../../scenarios/social_network_chat.yaml`; при расхождении источником истины является канонический файл.

## Что показывает пример

- Нагрузку 500 запросов/с в базовом режиме и 2500 запросов/с в пике.
- Долю чтений 0.6.
- Два функциональных требования: доставка личного сообщения онлайн/офлайн и подтверждение прочтения.
- Целевые ограничения по задержке и доступности.

Наличие требования в YAML не означает, что активная реализация валидирует его. В текущей композиции сервиса архитектуры подключены валидаторы бюджета, насыщения вычислительных узлов и теоретической задержки. Не представляйте требование доступности из этого примера как уже проверяемый SLA.

## Как получить реальные выходные артефакты

Из корня репозитория выполните:

```bash
uv run python scripts/generate_pipeline.py \
  --scenario docs/examples/social_network_chat.yaml \
  --out-dir output/presentation
```

Перед запуском настройте LLM endpoint по README и убедитесь, что модель доступна. Полный конвейер выполняет три этапа: C4, Sequence по каждому функциональному требованию, затем API. При успешной генерации в каталоге результатов ожидаются:

| Тип | Ожидаемые имена для этого сценария |
| --- | --- |
| Архитектурная модель | `social_network_chat_c4.json` |
| C4 | `social_network_chat_c4.puml` и `social_network_chat_c4.png` или `.svg` |
| Каталог ролей | `social_network_chat_roles.json` |
| Sequence для `req_msg_01` | `social_network_chat_seq_req_msg_01_ast.json`, `.puml` и изображение |
| Sequence для `req_msg_02` | `social_network_chat_seq_req_msg_02_ast.json`, `.puml` и изображение |
| Модель API | `social_network_chat_api_design.json` |
| OpenAPI | `social_network_chat_api_openapi.json` |
| Swagger UI | `social_network_chat_api_swagger.html` |

Это ожидаемый список, а не подтверждение уже выполненного запуска. Фактические файлы зависят от успешности генерации и рендеринга. Результаты LLM намеренно не подменены заранее написанными JSON или диаграммами: для презентации следует использовать артефакты именно того запуска, который был проверен вручную.

## Рекомендации для презентации

- Используйте один и тот же сценарий на слайдах про вход, C4, Sequence и API.
- Выберите по одному фрагменту из реально созданных файлов, а не вставляйте целые JSON-документы.
- Перед демонстрацией проверьте соответствие C4 и Sequence, содержимое OpenAPI и открытие Swagger UI.
- Не публикуйте ключи API, приватные входные требования и подробные логи. Флаг `--verbose` может выводить сырые ответы LLM.
- По умолчанию `config.yaml` использует `structured_output_mode: prompt` и `visualisation.server: auto`. Если входные данные чувствительны, настройте разрешённый способ доступа к LLM и локальный сервер PlantUML явно; не считайте конфигурацию локальной только по факту использования локальной модели.
