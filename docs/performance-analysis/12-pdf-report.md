# PDF-представление отчёта производительности

## Назначение

JSON — единственный источник значений. PDF является представлением **уже вычисленного**
`PerformanceAnalysisReport` и не вычисляет метрики повторно. Поэтому PDF и JSON
должны содержать одни и те же значения, включая различие между нулём и `null`.

## Как создаётся

При обычном запуске конвейера после успешной генерации C4 формируется
`<scenario>_performance_analysis.json`, затем рядом создаётся
`<scenario>_performance_analysis.pdf` с таблицей рассчитанных метрик, подтверждёнными рисками перегрузки
и списком критического синхронного пути.

Документ рендерится ReportLab, с встроенным TrueType-шрифтом из **установленных
системных шрифтов** (обычно DejaVu Sans в Linux и Arial в Windows).
Шрифты не коммитятся в репозиторий. Если автоматический путь недоступен,
при ручном использовании `PerformanceReportPdfRenderer(font_path=Path(...))`
можно указать путь к имеющемуся на машине Unicode TTF. Текст остаётся
выделяемым и пригодным для поиска.

## Сбой PDF не уничтожает JSON

JSON обязателен, PDF необязателен. Если отсутствует шрифт либо не удалось
записать PDF, стадия получает `StageStatus.PARTIAL`, сохраняет JSON
и пишет объяснение в `StageOutcome.warnings`. Ошибки вычисления JSON
не маскируются этим правилом. Статус стадии (успешно записаны артефакты)
и `PerformanceAnalysisStatus` (достаточно ли математических исходных данных)
**различны**: можно успешно вывести PDF с частичным или недоступным анализом.

## Содержание

1. Идентификатор сценария.
2. Рассчитанный синхронный путь с наибольшей суммой средних задержек.
3. Таблица существующих метрик: входящий RPS, пропускная способность,
   загрузка, среднее ожидание и время ответа. Столбцы без рассчитанных
   значений не печатаются.
4. **Только реально выявленные расчётом риски перегрузки**; уведомления о
   том, что модель не умеет рассчитать, в PDF не выводятся.
5. Одна короткая подпись о том, что данные расчётные, а не измеренные.

## Проверка

- `tests/unit/performance_analysis/test_pdf_renderer.py`: настоящий PDF,
  кириллица в извлечённом тексте, отсутствие метрик, длинные идентификаторы,
  многостраничность, отсутствие системного шрифта.
- `tests/unit/performance_analysis/test_stage.py`: два файла при успехе,
  только JSON и предупреждение при ожидаемой ошибке PDF.
- В CI используется реальный ReportLab и извлечение текста посредством pypdf.
- После рендеринга пользователю рекомендуется проверить PDF **визуально**:
  переносы, страницы, таблицы, кириллицу и читаемость. Успешный тест
  извлечённого текста сам по себе не доказывает отсутствие наложений.
