# Модель M/M/1

> **Сначала:** [теория массового обслуживания с нуля](QUEUEING_THEORY_FOR_BEGINNERS.md).
> **M/M/1** — не три случайных символа, а нотация Кендалла `A/S/c`:
> первая **M** = пуассоновские поступления; вторая **M** = экспоненциальное
> обслуживание; **1** = один независимый канал. «Без памяти» относится
> к распределению интервалов, а не к отсутствию состояния в приложении.

Практический вопрос этой модели: **сколько в среднем запрос проведёт в
ожидании и обработке, если один обработчик получает случайный поток?**
Представьте одну кассу и одну очередь: при увеличении потока кассир
работает почти постоянно, и время ожидания растёт непропорционально.

## Предположения

M/M/1 — модель одной очереди с одним независимым каналом обслуживания:

- входящий поток — пуассоновский с интенсивностью \(\lambda\);
- время обслуживания имеет экспоненциальное распределение с интенсивностью \(\mu\);
- есть один сервер, неограниченный буфер ожидания и дисциплина обслуживания FIFO;
- оценивается установившийся режим, который существует только при \(\lambda < \mu\).

Интенсивности измеряются в запросах в секунду. Это не модель для любого узла архитектуры автоматически: число независимых каналов должно быть обосновано, а не выведено из максимального количества запросов в полёте.

## Формулы

Коэффициент загрузки:

\[
\rho = \frac{\lambda}{\mu}
\]

Для устойчивой системы \(\rho < 1\). Среднее время ожидания в очереди:

\[
W_q = \frac{\lambda}{\mu(\mu-\lambda)}
\]

Среднее время в системе, включая обслуживание:

\[
W = W_q + \frac{1}{\mu} = \frac{1}{\mu-\lambda}
\]

Формулы дают время в секундах, если обе интенсивности заданы в запросах в секунду. В реализации результат переводится в миллисекунды умножением на 1000.

## Проверяемый пример

При \(\lambda = 10\) запросов/с и \(\mu = 20\) запросов/с:

- загрузка: \(\rho = 10/20 = 0.5\);
- среднее ожидание: \(W_q = 10/(20\cdot10) = 0.05\) с, то есть 50 мс;
- среднее время в системе: \(W = 1/(20-10) = 0.1\) с, то есть 100 мс.

При нулевом входящем потоке ожидание равно нулю, но время обслуживания остаётся равным \(1/\mu\).

## Неустойчивая система

Если \(\lambda \geq \mu\), конечная стационарная оценка среднего ожидания не существует для этой модели. Расчёт возвращает статус `unstable`, сохраняет коэффициент загрузки и оставляет времена ожидания и ответа равными `null`. В JSON не записываются `Infinity` или другие нечисловые значения.

Некорректные входные интенсивности (отрицательные, не конечные или нулевая интенсивность обслуживания) отклоняются. Если корректные входы приводят к значению за пределами диапазона конечных чисел с плавающей точкой, расчёт тоже завершается явной ошибкой, а не создаёт невалидный результат.

## Реализация

- Общий контракт результата: `src/domain/performance_analysis/queueing.py`.
- Чистая функция M/M/1: `src/domain/performance_analysis/mm1.py`.
- Числовые и граничные тесты: `tests/unit/performance_analysis/test_mm1.py`.

Модель остаётся независимой от стадии конвейера. Она пока не применяется ко всем узлам графа, поскольку семантика `maximum_concurrency` не доказывает наличие такого же числа независимых серверов.
