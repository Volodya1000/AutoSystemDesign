# Решение: проверяемость требований, извлечённых из документов

## Решение

Извлечение выполняется в два этапа. Сначала LLM выделяет атомарные утверждения и цитаты; затем приложение проверяет, что каждая цитата существует в исходном фрагменте и что само утверждение является её непрерывной дословной подстрокой. Неподтверждённые утверждения исключаются из набора, а причина сохраняется в диагностике.

На втором этапе LLM сопоставляет только проверенные утверждения с полями `DesignScenario`. Каждый заполняемый текстовый или числовой элемент сопровождается `source_excerpt`. Приложение проверяет принадлежность цитаты набору подтверждённых фрагментов; для чисел дополнительно проверяется наличие того же числового значения в цитате. Перевод процентов в дроби, преобразование единиц и вывод значений по умолчанию запрещены.

Результат записывается в обычный YAML-формат `DesignScenario`, который принимает существующий `scripts/generate_pipeline.py`. Отдельный JSON-манифест содержит цитаты по полям и предупреждения. Неизвестные значения не подменяются догадками. Например, отсутствие `read_ratio` отмечается явно, потому что текущая доменная модель при загрузке YAML применяет значение по умолчанию `0.8`.

## Обоснование

JSON Schema и Pydantic проверяют структуру и типы, но не доказывают истинность текста. Проверка точных цитат и буквального присутствия числа переносит часть гарантий в детерминированный код. На первом этапе требование нельзя перефразировать: его формулировка должна быть подтверждена цитатой дословно. При сопоставлении со сценарием функциональный текст и описание также должны быть дословными подстроками указанной цитаты. Это консервативно и может пропустить корректный пересказ, зато не пропускает новый факт только потому, что рядом приведена настоящая, но не относящаяся к нему цитата.

Эти проверки не являются полной формальной проверкой логического следования: например, выбор типа метрики по смыслу остаётся классификацией LLM. Поэтому манифест цитат сохраняется для проверки пользователем, а неподдержанные значения и цитаты отбрасываются.

## Границы

- Текущая реализация поддерживает Markdown; `DocumentReader` остаётся собственным узким портом.
- LangChain не нужен ради чтения текста из одного формата. Docling следует подключать отдельным инфраструктурным адаптером вместе с интеграционными тестами PDF/DOCX/HTML/OCR.
- YAML-конвейер не меняется: генератор документа выдаёт совместимую с ним модель и сохраняет доказательную трассировку отдельно.
