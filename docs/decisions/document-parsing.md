# Решение: извлечение текста из документов

## Решение

Приложение зависит от собственного порта `DocumentReader` в application-слое.
Для каждого формата инфраструктура предоставляет отдельную стратегию чтения.
Первая реализация поддерживает Markdown без дополнительной библиотеки.

Для будущей поддержки PDF, DOCX, HTML и OCR предпочтителен отдельный адаптер на базе
[Docling](https://github.com/docling-project/docling), который преобразует документ в
текстовое представление до извлечения требований. Конкретная зависимость не должна
просачиваться в application-слой.

## Почему не LangChain

LangChain полезен как orchestration/framework-слой, но здесь нужен узкий контракт
«путь к документу -> текст». Добавление его parser abstractions ради одного вызова
увеличит количество зависимостей и усложнит тестирование без текущей выгоды.

Docling ориентирован на разбор документов и сложных форматов; его следует подключать
только вместе с реализацией и тестами соответствующего формата. Не добавляем его в
зависимости на этапе Markdown MVP, чтобы не утяжелять установку и CI.

## Ограничения

Извлечение текста не гарантирует корректность смысла исходного документа. OCR,
таблицы, колонки, подписи к изображениям и ссылки на внешние приложения потребуют
отдельных интеграционных тестов и явной диагностики нераспознанного содержимого.
