# Реальный отчёт SimPy без LLM

```bash
uv sync --locked --all-groups
uv run python scripts/run_offline_simulation_demo.py --output-dir output/simpy_demo
```

Программа читает `examples/simulation/cache_demo.json`: C4-граф, нагрузку, требования и конфигурацию. Нет генерации архитектуры, вызова LLM, API-ключей или отдельной сборки PDF вручную.

Для другого поддержанного графа: `--input path/to/input.json`. Формат входа проверяет `OfflineSimulationInput`; используются существующие `ArchitectureGraph` и `DesignScenario`.

## Что создаёт команда

- `offline_cache_simulation.json`: канонический `SimulationReport` с исходами запросов, описательными квантилями прямого пути, посещениями узлов, требованиями и ограничениями.
- `offline_cache_simulation.pdf`: представление тех же значений, построенное `SimulationReportPdfRenderer` внутри программы. Рендерер не пересчитывает квантили, потери или вердикты.
- `offline_cache_simulation_trace.json`: полный вход, отображённый план, необработанные наблюдения и канонический отчёт для проверки воспроизводимости.

## Пример и независимая проверка

Физические связи: client → api, api → cache, api → db. БД вызывается самим API только при промахе кэша; связи cache → db нет.

Одна реплика и один канал каждого узла. Время обслуживания API - 50 мс, кэша - 3 мс, БД - 20 мс; дисперсия нулевая. Сетевая задержка каждого ребра - 4 мс. Hit rate - 80%, seed - 20261022. Окно - 10 секунд. Поступления равномерные.

Без очереди попадание занимает `4 + 50 + 4 + 3 = 61 мс`; промах - `61 + 4 + 20 = 85 мс`. Максимальный темп обслуживания API - 20 запросов/с; заданные 80 запросов/с превышают его вчетверо.

| Режим | Поступило | Завершено | Отказано | Незавершено | p50 / p95 / p99 прямого пути, мс |
| --- | --- | --- | --- | --- | --- |
| 10 запросов/с | 100 | 100 | 0 | 0 | 61 / 85 / 85 |
| 80 запросов/с | 800 | 199 | 595 | 6 | 311 / 335 / 335 |

Все отказы в примере происходят на API. Проверяется `поступило = завершено + отказано + незавершено`. Незавершённые не исчезают после достижения горизонта; дополнительного drain-интервала нет.

## Границы результата

Это рабочая вертикаль для проверки исходных данных, движка и отчётности. Она не заменяет этапы 6B–11 дорожной карты и не делает корневой #114 готовым к master.

- Прямой путь не является полной клиентской задержкой: обратный ответ не моделируется. Поле `client_latency_milliseconds` остаётся пустым; измерения записаны в `forward_path_latency_milliseconds`.
- Квантили рассчитаны inclusive-интерполяцией по завершённым запросам одного прогона. Это описательные значения без статистического доказательства выполнения SLO. Отказы и незавершённые заявки показаны отдельно.
- Посещения считаются только для завершённых root-запросов; это не все события обслуживания узла.
- Нет временных средних очередей/utilization и доверительных интервалов. Поля без измерений остаются null.
- Требование клиентской задержки и availability получают `not_evaluated` с причинами; перегрузка сама по себе не доказывает нарушение availability SLA.
- Демонстрация требует нулевого прогрева и одной репликации. Неподдержанная конфигурация приводит к явной ошибке.

Второй реальный PDF-рендерер позволил вынести общую типографику в `infrastructure/reporting/pdf/`. Регрессионные тесты аналитического PDF сохранены. Workflow `Offline SimPy report` запускает эту же команду и публикует результат как артефакт.
