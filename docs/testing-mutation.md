# Мутационное тестирование (mutmut)

`mutmut` меняет выражения и условия в коде и проверяет, выявляют ли тесты эти ошибки. В отличие от процента покрытия, мутационный анализ помогает оценить содержательность утверждений в тестах.

## Пилотная область

Для первого этапа исследуется `src/domain/models/base_constraints.py`: сравнения порогов, проверка диапазонов и обработка численных требований. Остальной код **пока не проверяется** mutmut; расширять область следует после анализа выживших мутаций.

Изолированное окружение mutmut получает также `scripts/`, `scenarios/` и `config.yaml`: они нужны существующим тестам. Это не расширяет область мутаций. Проверки границ находятся в `tests/unit/domain/test_numeric_requirements.py`.

```bash
uv sync --locked --all-groups
uv run --with mutmut==3.7.0 mutmut run
uv run --with mutmut==3.7.0 mutmut results
```

Запуск требует Linux или WSL (системный вызов `fork`). В GitHub Actions: `Mutation tests`, вручную через `workflow_dispatch`, по понедельникам в 03:00 UTC и на PR, меняющих пилотный модуль, его граничные тесты, конфигурацию или сам workflow. Другие PR эту проверку не запускают. Ограничены два параллельных процесса; результаты сохраняются в артефакт `mutation-results`.

**Критерий дальнейшего ужесточения:** разобрать выжившие мутации, дополнить независимые поведенческие тесты и только затем включать блокирующий порог на изменения. Эквивалентные мутации могут не обнаруживаться тестами без реального дефекта.

Проверка 22 октября 2026: первоначально выжили 13 мутаций пороговых сравнений, а две мутации интервала не имели тестов. Добавлены 14 граничных проверок. Чистый повторный запуск уничтожил 15 из 17 мутаций. Две оставшиеся меняют fallback неизвестного оператора; при валидном `Operator` эта ветвь недостижима. Искусственно подавлять эти мутации или обходить Pydantic в тесте не нужно.

Новый инструмент устанавливается командой `uv run --with` с фиксированной версией без изменения `uv.lock`.
