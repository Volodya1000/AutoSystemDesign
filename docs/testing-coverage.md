# Покрытие модульных тестов

CI запускает `pytest-cov` в задаче `Unit tests` и публикует `coverage.xml` как артефакт `unit-test-coverage`.
Измеряются строки и ветви Python-кода из `src/`; интеграционные тесты с настоящей LLM в расчёт не входят.

Запуск локально (дополнительный инструмент ставится в отдельное окружение `uv --with`, поэтому `uv.lock` не меняется):

```bash
uv run --with pytest-cov==7.0.0 pytest tests/unit --cov=src --cov-branch --cov-report=term-missing --cov-report=xml:coverage.xml
```

Обязательный минимум суммарного покрытия строк и ветвей: **88,50%**. Он задан один раз в `pyproject.toml` (`tool.coverage.report.fail_under`); его используют GitHub Actions и pytest-хук pre-commit. Результат ниже порога завершает проверку ненулевым кодом. Точность отчёта - два знака: округление до целых не маскирует падение.

Измеренная база на 22 октября 2026: 516 unit-тестов; 4121/4520 строк и 756/986 ветвей. Суммарно `(4121 + 756) / (4520 + 986) = 88,5761%`. Поэтому выбран проходящий порог 88,50%, близкий к текущей базе. Повышать его нужно вместе с содержательными тестами. Новые исключения из покрытия ради прохождения порога недопустимы.

Процент покрытия **не гарантирует** качество проверок. Для оценки способности тестов обнаруживать ошибки используются мутационные тесты.
